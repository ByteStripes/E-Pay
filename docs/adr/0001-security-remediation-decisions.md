# ADR-0001: 安全审计修复方案决策

## 状态
已接受 (2026-05-24)

## 背景
从第三方购入 E-Pay 支付系统代码后，全面安全审计发现 27 个安全漏洞（8 严重、11 高危、8 中危）。系统尚未上线，需在部署前完成全部修复。目标运行环境为 PHP 8.0+。

## 决策

### 1. SQL 注入修复：最小改动策略
**选择：** 保持 PdoHelper 现有 API，修复 `_where()` 字符串拼接漏洞，将 50+ 处调用方改为参数化查询。
**放弃：** 彻底重写数据库层。
**原因：** PdoHelper 已有安全的参数化方法，问题在调用方。重构数据库层风险大、收益小。

### 2. 认证加密升级：保持架构换算法
**选择：** 保持 Cookie Token 架构，将 authcode (RC4) 替换为 sodium_crypto_secretbox (XSalsa20-Poly1305)。
**放弃：** 迁移到标准 PHP Session 机制。
**原因：** 架构本身无问题，仅算法过弱。替换一个函数比重写认证流程风险低得多。

### 3. 密码哈希：MD5 → password_hash(ARGON2ID)
无向后兼容负担（数据库为空），直接替换。移除硬编码盐值。

### 4. CSRF 防护：全局中间件 + 白名单
**选择：** 在 common.php 统一生成/验证 CSRF Token，白名单排除 gateway.php、api.php、mapi.php、cron.php。
**放弃：** 逐文件手动添加。
**原因：** 默认安全原则，新增页面自动受保护。

### 5. 反序列化：全面替换为 JSON
**选择：** serialize/unserialize → json_encode/json_decode。
**放弃：** 保留 unserialize + allowed_classes 限制。
**原因：** 数据库为空无迁移负担，JSON 更安全、更可读、跨语言兼容。

### 6. XSS 防护：输出函数层默认转义
**选择：** 修改 showmsg/sysmsg 等全局函数内部默认做 htmlspecialchars 转义，需要原始 HTML 的场景通过显式 $raw 参数。配合 CSP 头部纵深防御。
**放弃：** 在每个调用方逐一转义。
**原因：** 默认安全，避免遗漏。

### 7. install 目录：保留 + 认证保护
保留安装代码以备首次部署，但 update.php 加管理员认证，强化 install.lock 检测，部署文档注明上线后禁止外部访问。

### 8. 修复范围：全部漏洞一次修复
趁上线前窗口期清零所有已知风险（Critical + High + Medium），不留技术债务。

## 后果
- 所有已知安全漏洞在上线前修复完毕
- 认证 Cookie 格式变更（RC4→sodium），与旧版不兼容（可接受，未上线）
- 数据库序列化字段改为 JSON 格式（可接受，数据库为空）
- 密码哈希格式变更（MD5→ARGON2ID），旧格式不兼容（可接受，无存量用户）
